## 一、要解决的问题

装箱任务由 **4 个独立的 π0.5 策略模型**（专家）接力完成，每个专家内部又分成若干子任务：

| 专家 | 子任务数 | 内容 |
|---|---|---|
| E1 右臂抓放 | 2 | 抓盒子 → 放进纸箱 |
| E2 左臂抓放 | 2 | 抓盒子 → 放进纸箱 |
| E3 封箱中段 | 7 | 撑翼 → 内折压平 → 退开 → 推下翼… |
| E4 封箱末段 | 7 | 移到翼片上方 → 撑住 → 掰起 → 内折… |

要自动化就得回答两个不同性质的问题：

- **该由哪个模型接管** → 换推理服务（换端口、换 checkpoint）
- **模型内部该做哪一步** → 同一模型不变，换喂给它的 **prompt**

π0.5 是**语言条件策略**：同一套权重，喂"抓盒子"就去抓，喂"放进箱子"就去放。
所以第二层切换的本质是 **"在正确的时刻换那句话"**。

**核心约束（贯穿全部设计）**：部署时网络卡顿会让机械臂停在原地。
所以模型**只吃当前帧** —— 不喂帧号、不喂已执行时长、不用任何时序模型。
卡住时输入不变 → 输出不变 → 进度天然不推进。

## 二、方法

### 2.1 标签：零人工

数据集里 `prompt_index` 逐帧记录，同一子任务是一段**连续游程**，游程起止即边界。
对每段 `[s, e]`（`L = e − s`）导出三种标签：

```
p_t    = (t − s) / L                      线性进度
done_t = 1[ t ≥ e − 4 ]                   段末 5 帧软窗口
ttb_t  = clip((e − t) / 30, 0, 1)         距边界归一距离
```

导出 **236,957 帧 / 1,583 段 / 369 集，顺序异常 0 集**，事件锚点数与段数完全对齐。
不需要任何人工标注。

> ⚠ **标签用了时间，但模型输入里没有任何时间量** —— 这是抗卡顿的根本，
> 也是最容易被误解成"按采集时长切换"的地方。

### 2.2 特征：SigLIP2 冻结塔

三路 RGB → SigLIP2-so400m（**冻结不训练**）→ 1152 维 × 3。
视觉塔冻结所以特征可一次性缓存，之后训练是纯 MLP，一轮几十秒。

> ⚠ 解码必须用 **PyAV**：两路腕部相机是 AV1，`cv2` 会**静默**失败并产出全零特征。

### 2.3 进度头：一个小 MLP，三个输出

图像特征 + state + (专家id, 子任务id) → `p` / `done` / `ttb`。
各专家 state 语义不同（E1/E2 是 10 维单臂末端位姿，E3/E4 是 20 维双臂），
所以**每个专家配一个独立的 state 编码器**，不做 padding 混用。

**为什么要三个头**：`p` 把容量摊在整段上，但决策只发生在段末几十帧；
`done` 是分类、输出天然贴 0/1；`ttb` 在离边界 >30 帧处恒为 1，容量全给边界附近。
三者取最小值 = **三个信号都认为该切了才切**。

**损失**：`SmoothL1(p) + 1.0·BCE_w+(done) + 0.1·单调性 + 2.0·SmoothL1(ttb)`

### 2.4 标定：τ、延迟 D、兜底步数

全部按 **(专家, 子任务)** 分别标定，**只用训练集**，留出集仅用于报告。

```
τ_sub = Quantile_q( sustained_K(EMA(sig)) )      其中
        sustained_K(sig) = max_i min_{j∈[i,i+K)} sig_j
D_sub = −median(训练集触发误差)                   补早触发偏置
M_sub = 1.5 × p95(训练段长)                       漏切兜底
```

> ⚠ **τ 必须用"可持续 K 帧的值"而不是峰值**。触发规则要求连续 K 帧过线，
> 瞬时峰值 0.97 但只闪一帧的段，用峰值标定出的 τ 根本触发不了 ——
> 这一条占了早期 **41% 漏切**的绝大部分。

### 2.5 部署决策链

```
sig = min(p, σ(done), 1−ttb)
  → EMA_t = α·sig + (1−α)·EMA_{t−1}
  → 连续 K 步都 > τ
  → 再等 D 步（按推理步计，非墙钟时间）
  → 换 prompt
```

**停滞门控**：`freeze = (‖Δstate‖∞ < ε) ∧ (sig ≤ τ)`，冻结 EMA 与所有计数器。
后半个条件是关键 —— 要防的是"卡顿期间 EMA 慢慢爬过阈值"这种假阳性；
若信号已过线，静止说明"做完了停在那儿"，该切就切。

**第一层（专家之间）不用模型**：6 个盒子是已知确定量，用计数器 + 进度头的
`finished` 标志即可，数计数器比数模型准。

## 三、结果

### 3.1 策略模型训练（📊 图 04）

| 模型 | 步数 | 耗时 | 起始 loss | **最终 loss** |
|---|---|---|---|---|
| 左臂抓盒子 EE | 20k | 9h40m | 0.0816 | **0.0068** |
| 封箱末段 v2 | 20k | 21h20m | 0.3747 | **0.0224** |
| 封箱末段 v100 | 20k | 进行中 | 0.3836 | 0.0267（当前） |

三条曲线均平滑单调下降、末段趋平，无震荡无反弹。
左臂起点低一个量级、终值低 3 倍多 —— 它只是两段式单臂抓放，
而封箱末段是 7 子任务双臂协调，难度不在一个量级。

### 3.2 进度头切换准确率（📊 图 05）

**串行回放**口径（整集跑状态机，第 n 段起点是上一段**实际**切走的位置，误差会累积
—— 比分段评估严格，也是真机行为）：

| 专家 | 整集跑完 | 切换数 | ≤10帧 | ≤20帧 |
|---|---|---|---|---|
| E1 右臂抓放 | 18/18 | 36 | 69% | 94% |
| E2 左臂抓放 | 16/16 | 32 | 78% | 94% |
| E3 封箱中段 | 25/25 | 175 | 73% | 89% |
| **E4 封箱末段** | 14/14 | 98 | **84%** | 91% |
| **合计** | **73/73 = 100%** | 341 | **76%** | **91%** |

E4 最准（封箱末段翼片状态视觉区分度高）。数据集 15 fps，所以 20 帧 = **1.33 秒**。

### 3.3 决策规则的修正历程（📊 图 06）

**同一个模型，只改判据**：

| 阶段 | 正确切换率 |
|---|---|
| 起点（τ=0.85 固定） | 22% |
| + 正确选点准则（sustained-K 标定、EMA） | 36.4% |
| + ttb 头 | 40.7% |
| + 训练集标定 τ 与延迟 D | 67.1% |
| + 三视角 | **73.8%** |

主指标定义为 **"触发了 **且** |误差| ≤10 帧"**，漏切自动算失败。
早期按"漏切率最低"选点是错的 —— 会退化到 τ→0，从不漏切但**提前 86 帧**触发。

### 3.4 三类鲁棒性（📊 图 07）

**抗卡顿**

| 测试 | 结果 |
|---|---|
| 静止 30 帧的进度漂移 | **0.0000** |
| 注入 90 步卡顿（走真实部署代码） | 门控冻结 90/90，切换偏移 **0 帧** |
| 同上但门控失效 | 仍全部跑完，但最坏出现 **45 帧**偏移 |

→ 扛住卡顿的主力是「只吃当前帧」这个设计本身，门控是第二道保险。

**相机移位**（同一批 12 集，两个包跑同一份数据）

| 情形 | 干净版 | 几何增强版 |
|---|---|---|
| 无扰动 | 11/12 | **12/12** |
| 第三视角 平移3% | 10/12 | **12/12** |
| **第三视角 平移6%** | **8/12（4 集卡死）** | **12/12** |
| 第三视角 缩放1.08 | 12/12 | **12/12** |

→ 这是采用增强版的**唯一**理由；干净数据上两者打平。

**速度 / 调用频率**

| 相对速度 | 整集跑完 | 视觉位置误差 | ≤8%段长 |
|---|---|---|---|
| 0.5× | 59/60 | −8.7% | 45% |
| **1.0×（15 Hz 标定点）** | 59/60 | **+0.0%** | **76%** |
| 2.0× | 72/73 | +11.1% | 32% |
| **3.0×（=按 5 Hz 调用）** | **64/73** | **+23.6%** | **4%** |

→ **模型本身对速度不敏感**（跑完率全程不变），但判据里 D/K/EMA 都是**步数量纲**，
调用频率一降就成倍放大。**部署时 `sw.step()` 必须按 15 Hz 调用。**

### 3.5 消融与负结果（📊 图 08）

**视角消融**：三视角 78% > 仅腕部 74% > 仅第三视角 67%。
这**推翻了原定的"只用第三视角"方案** —— 原理由是"腕部随手臂动 = 时间性线索"，
但 `observation.state` 本来就是所有版本的输入，相位信息第三视角版早就有；
腕部多出来的是**夹爪附近的细粒度世界状态**（东西抓住没有、盖子贴合没有）。

**输入消融**：图像+state 0.2476 ≈ 只有图像 0.2571 ≪ 只有 state 0.3297。
→ **判断进度主要靠画面，不是靠末端位姿。**

**四条改进路径全部无效**（都在噪声带内）：

| 尝试 | 三种子均值 | 结论 |
|---|---|---|
| 基线（定稿） | **75.0%** | — |
| 多头集成 ×3 | 74.0% | 无提升 |
| 加第二份几何增强 | 75.7% | 无提升 |
| 网格池化 2×2 特征 | 74.3% | 无提升 |
| E2 换成末端位姿 | 74.3% | 无提升 |

**噪声标尺**：只换随机种子，指标就在 **72%~77%** 摆动 →
在这个留出集上**小于约 5 个点的差异都是噪声**，必须 3 种子比均值。

其中"网格池化"那条最有信息量：我原本认定 `pooler_output` 的全局池化抹掉了
"盒子在不在夹爪里"这类**空间局部**信息，是 76% 天花板的成因。
改成保留 2×2 空间网格后并没有变好，**这个假设被证伪了**。

**结论**：残余误差不是特征或容量不够，而是**单帧进度估计的固有歧义** ——
同一段动作在 45% 和 55% 处，画面和 state 都几乎一样。
能打破它的手段（时序上下文）正是抗卡顿约束明确排除的。
所以 **76% 是这套方法在这份数据上的天花板**，而 ≤20 帧已有 91%（1.33 秒），
对切 prompt 完全够用。

### 3.6 专家级图像分类器：不可行（负结果）

按原方案训了 E1/E2/E3 三分类：**逐帧准确率 epoch 0 就 100%、混淆矩阵全对角**，
但**时序剖面完全平坦** —— E1 集直到 90% 进度，预测为 E3 的概率仍是 0%；
E3 集从第 0 帧起就是 100%。

这是**捷径学习**：它学的是"这帧来自哪个数据集"（录制时段、光照、机位），
不是"现在该切换了"。部署后果很明确 —— E1 放完盒子后画面仍是 E1 场景，
分类器永远说 E1，**握手永远不会触发**。

**根因：决策边界不在数据里**。数据集分别录制，没有任何一集横跨
"箱子没满 → 装满 → 开始封箱"这个转变。缺的是**数据**，不是模型或超参。

## 四、上机前两件必做

1. **`sw.step()` 按 15 Hz 调用**（数据集帧率）。按 5 Hz 调用准确率从 76% 崩到 4%
2. **停滞阈值在真机相机上重标**。包里的 `stall_img_eps` 是压缩视频上标的
   （H.264 把静止区域量化成完全相同的块），真机相机噪声会让门控**永远不触发**；
   所以图像通道默认关闭、主判据用 `Δstate`
